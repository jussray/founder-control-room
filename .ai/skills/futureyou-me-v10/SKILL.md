# FutureYou/Me V10 — FCR adapter

This adapter integrates founder-intent orchestration into Founder Control Room without replacing the FCR constitution, existing skills, product identity, or authority boundaries.

## Read first
- `AGENTS.md` and `CLAUDE.md`
- `.ai/skills/juss-founder-os/SKILL.md`
- `AGENTS_FOUNDER_INTELLIGENCE.md` and `docs/FOUNDER_INTELLIGENCE_CONSTITUTION.md`
- `GLOBAL_AI.md`
- `docs/FOUNDER_MERGE_AUTHORITY.md`
- `skills/devil/SKILL.md`
- Applicable repository-specific skill and runtime contracts

The stricter FCR rule always wins. V10 is an optional orchestrator, not a new approval, publishing, mutation, merge, or deployment grant.

## Portable source
Upstream proposed skill: `jussray/ULTRATHINK-` branch `skill/futureyou-me-v10`, `.claude/skills/futureyou-me-v10/SKILL.md`. Do not treat an unmerged branch as canonical or live.

## Operation
When an authorized agent invokes `/godmode`, `/ultrathink`, `/devil`, `/redteam`, `/lindymode`, `/ooda`, `/l99`, `/goalfix` or `/loop`:
1. Establish exact repo, branch, SHA, goal, write owner, risk, and stop condition.
2. Red Team I: challenge the need, authority, and smallest alternative. Use FCR's existing `skills/devil/SKILL.md` rather than replacing it.
3. Lindy/L99: prefer durable, reversible work and evidence-bound claims.
4. OODA: inspect, decide, execute only permitted actions, then independently verify.
5. Red Team II: test failure paths, stale state, permissions, privacy, and rollback.
6. Report REALITY, FIX, PROOF, RISK, ROLLBACK, NEXT GATE. Distinguish VERIFIED, INFERRED, UNKNOWN, BLOCKED.
7. Leave exact-head receipts only in approved storage. Never claim a receipt, test, live runtime, or activation without proof.

No automatic command registration is implemented by this Markdown adapter. All founder-final merge approval must identify exact repository, PR, base SHA and head SHA; generic `approved` or `cont` is not merge approval.
