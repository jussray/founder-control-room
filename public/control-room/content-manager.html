First-party conveyor

Progress → story → verify → Current You → review window → provider receipt → learning

Each stage owns a different truth. A green upstream stage cannot silently paint the next stage green.

  1. 1

    Verified progress

    Scope claims to exact current project evidence before writing public copy.

    State → Evidence → Claim
  2. 2

    Chief story

    Turn proof into a human founder narrative while withholding the proprietary mechanism.

    proposal_only = true
  3. 3

    FCR verify

    Recompute the Chief identity, verify proof scope and sauce receipt, and reject mutated copy.

    exact proposal + copy hash
  4. 4

    Current You

    Bind fresh authenticated intent to the exact public copy. Replay, revocation, or stale intent fails closed.

    exact-current-you
  5. 5

    Review window

    Route only authorized copy into the governed Buffer review-window lane. No instant share.

    share_now = false
  6. 6

    Provider receipt

    Read back external state before calling anything scheduled or published.

    provider truth required
  7. 7

    Outcome learning

    Measure qualified outcomes. Missing metrics stay UNKNOWN, and analytics can never increase authority.

    UNKNOWN ≠ 0

Chief AI owns

Story intelligence

  • Founder angle, hook, and framing.
  • Verified public claim proposal.
  • Disclosure-minimized copy.
  • No approval or provider write.

Founder Control Room owns

Authorization and evidence

  • Independent Chief-packet verification.
  • Exact Current-You publication authorization.
  • Review-window routing.
  • Privacy-safe outcome receipts.

Providers own

External delivery

  • OAuth/account identity.
  • Actual schedule/publication state.
  • Provider retries and errors.
  • Native engagement readback.

Truth boundary

First-party authorization does not mean a provider write already happened.

FCR can verify, authorize, and hand off an exact public payload. A provider receipt must still be read back before “published” becomes true.
