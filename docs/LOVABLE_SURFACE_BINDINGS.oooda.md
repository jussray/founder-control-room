# Lovable surface OODA

## Observe

Three Lovable surfaces exist. Truth Compass has a durable Supabase backend but incomplete UI. Exact Match Engine currently uses seeded browser-local state. Truth Weaver is an incomplete reasoning surface.

## Orient

External builder surfaces should point at canonical repositories, not enter the authority-bearing portfolio allowlist. Founder Control Room stays the project truth and authority plane; Chief stays the reasoning/proposal plane.

## Decide

Publish one public-safe, cross-origin-readable repository binding manifest and validate it in the ordinary FCR test suite. Bind each Lovable project's own knowledge to the same relationship.

## Act

Add the manifest, schema, headers, focused tests, and explanatory receipt without touching provider credentials, product databases, portfolio authority, merge/deploy authority, or external mutation paths.

## Verify

Require exact-candidate FCR lint, typecheck, full tests, Required Gate, security analysis, and Pages deployment before treating the repository binding as current. Require a separate Lovable authenticated runtime/browser receipt before claiming the external surfaces actually consume FCR data.

## Loop

When either the external surface or canonical repository moves, re-observe both identities. The surface commit is continuity evidence only and the repository HEAD must always be resolved fresh.
