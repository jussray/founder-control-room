# External surface Attack Ten

These checks are requirements for the Lovable-to-repository binding and do not grant execution authority.

1. A Lovable project ID cannot become a portfolio project merely by existing.
2. A Lovable preview URL cannot prove repository HEAD, deployment equivalence, or publication state.
3. A stored surface commit cannot be reused as current repository proof after either side moves.
4. Browser-local or seeded state cannot be substituted when Founder Control Room data is unavailable.
5. World evidence cannot promote project truth to VERIFIED by itself.
6. A reconciliation result cannot grant merge, deploy, publish, spend, provider, or credential authority.
7. Truth Weaver reasoning, model choice, strategic lenses, or confidence cannot widen authority.
8. Distinct failures cannot be collapsed into one green or blocked status when separate receipts exist.
9. The public binding artifact must contain no secrets, raw private evidence, customer/user content, or private founder state.
10. A green source contract is not live integration proof. The external surface must still prove its real authenticated runtime and data path independently.
