# Private storyboard job bridge

Source-only operator workflow; no live generation or fidelity verification is established by this bridge. Keep input files and output plans outside public repositories. Do not supply personal user recordings or emotional content. Source binding and budget approval records must be obtained from trusted reviewed records, not member/browser assertions. A matching digest is not proof of founder identity.

Run with Node and installed project dependencies:

```sh
node --import tsx scripts/storyboard-media-jobs.mts --action fingerprint --storyboard /private/storyboard.json
node --import tsx scripts/storyboard-media-jobs.mts --action compile --storyboard /private/storyboard.json --binding /private/binding.json --output /private/plan.json
node --import tsx scripts/storyboard-media-jobs.mts --action queue --storyboard /private/storyboard.json --binding /private/binding.json --approvals /private/budgets.json --root /private/media-jobs --output /private/queued-plan.json
```

`PrivateStoryboard` and `StoryboardSourceBinding` in `src/lib/storyboardMediaJobBridge.ts` define inputs. The source binding must name the project, reviewed source record and exact storyboard fingerprint. Each ordered shot carries a unique ID, exact dialogue (empty for silence), canonical reference digest, approved opening-frame file/hash, prompt and integer duration of 2–10 seconds. The storyboard binds one exact assembly audio file/hash and 24/25/30 fps. Limits: 120 shots, 60–1200 seconds, 720×1280 vertical output, 1000 prompt characters per shot. Split longer shots explicitly in the approved storyboard; do not silently extend or reorder them. Maximum audio file size is 512 MiB. This bridge does not inspect actual audio duration.

The compiled private plan includes each request and its input fingerprint. Supply one separate `MediaJobApproval` per shot in exactly that order, with project/adapter/fingerprint, explicit positive per-job budget, source record and future expiry. No approval is generated by this command. Queueing verifies local audio bytes and uses `DurableMediaJobs` to snapshot/hash frame bytes. Queueing never submits a provider job. Use existing `scripts/media-job.mts` separately for submit/poll/materialize only after reviewing provider eligibility, credential configuration and exact spending approvals.

The audio is retained for final assembly only; it is not sent to Runway. Script/canon/audio/order changes invalidate all job fingerprints. Outputs remain `REVIEW_REQUIRED`; fidelity, exact mouths, silence and lip sync require human/encoded-media review. Final assembly must recheck the approved audio hash, its full duration, shot order, frame counts, source lengths and no freeze-padding. No output from this bridge is publication authority.

The CLI never overwrites output files and writes mode 0600. Failure can leave earlier jobs queued; preserve the failed handoff and reconcile existing fingerprinted job records before retrying to a new output path. No paid call is made by compile or queue. Local behavior tests use synthetic files and an unused fake external transport; they establish queue contracts only.
