# Model-Native Execution Profiles

Founder Control Room keeps one evidence-backed reality while allowing different models to work in the way that best fits their observed runtime.

## Invariant

Model differences may change **how work is done**. They may not change **what is true**.

The model-native layer may adapt context packaging, reasoning strategy, tool selection, handoff format, and verification plan. It may not adapt truth state, authority state, founder approval, proof state, or project canon.

Model agreement is never proof. A truth-state upgrade requires independent evidence from the authoritative repository, provider/runtime, tests, Playwright where applicable, or another current source named by the owning project contract.

## Runtime discovery

`chatgpt-sol` and `claude-code` are execution-profile identities, not permanent claims about a provider's current model build or enabled tools. Every run must observe the actual runtime model identity and currently available capabilities before relying on them. Missing tools are not simulated.

### ChatGPT Sol profile

Bias toward cross-system reconciliation, connector/tool orchestration, multimodal product analysis, and founder-readable decision synthesis.

### Claude profile

Bias toward long-context repository analysis, focused implementation, careful refactor planning, and structured documentation.

These biases guide routing only. Neither profile receives additional GitHub, Supabase, Cloudflare, billing, publication, deployment, merge, or founder authority from its model identity.

## Shared handoff

Every consequential model handoff should preserve:

- model profile id and observed runtime model;
- observed capabilities rather than assumed tools;
- authoritative truth references;
- authority required and proof required;
- claims and unknowns;
- continuity fingerprint;
- result evidence.

Chief may compile a model-native work plan. PromptOS may compile provider-specific prompts/protocols. Founder Control Room remains the shared truth, authority, evidence, and outcome plane. Recipients independently verify evidence before promoting a claim.

## Failure rule

If two models disagree, do not average, vote, or treat consensus as authority. Reacquire the evidence that governs the disputed claim. Preserve the losing claim as historical reasoning if useful, but never let model confidence overwrite observed reality.
